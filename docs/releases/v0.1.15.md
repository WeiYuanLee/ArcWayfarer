## 本次更新

### ArcWayfarer v0.1.15：更穩定的 iPhone GPS 定位模擬、背景執行與多裝置控制

ArcWayfarer v0.1.15 強化 macOS 與 Windows 上的 iPhone／iPad GPS 定位模擬體驗。即使將視窗最小化、切換至背景，或同時管理多台 iOS 裝置，種花與路線任務仍可持續執行；重新開啟視窗後，地圖、裝置與任務進度會自動恢復同步，不必重啟 App 或電腦。

### 背景執行更可靠，地圖恢復更順暢

- 修正種花模式或路線執行期間將視窗縮到最小，還原後地圖可能長時間卡頓、反白或無法繼續繪製的問題。
- 高效能地圖現在可處理 WebGL 繪圖環境遺失與恢復，視窗重新顯示時會自動校正尺寸、重繪路線並同步定位標記。
- 標準地圖也會在視窗恢復後重新校正尺寸，避免底圖與控制項錯位。
- 修正 WebGL 已恢復但畫面仍持續顯示「著色中」的問題。
- 若高效能地圖無法恢復，可單獨重新載入地圖或切換至標準模式，不會影響整個操作介面。

### 多台 iOS 裝置管理更穩定

- 三個操作席位會保留原有裝置，並優先保留執行中或暫停中的任務；每 20 秒重新掃描時，即使裝置回傳順序改變，也不會把正在種花的裝置移至等待區。
- 裝置遮蔽設定會依序號保存；重新偵測到同一台裝置後，仍會維持原有設定。
- 遮蔽操作會立即保留使用者意圖，避免還原真實定位與裝置重掃同時發生時，裝置短暫重新占用席位。
- 已遮蔽裝置恢復顯示時，若三個席位已滿會先進入等待區，不會取代目前正在使用的裝置。
- 等待區若有仍在背景執行的任務，可直接停止任務並還原真實 GPS 位置。
- 視窗恢復後會自動重新掃描裝置；背景掃描需連續兩次找不到裝置才會將其移出畫面，降低連線服務尚在恢復時誤判斷線的機會。

### 種花模式與路線進度保持同步

- 多點巡迴與種花草稿會依裝置個別保存；即使裝置暫時進入等待區、面板重新建立或畫面重新載入，原始點位與設定仍可恢復。
- 重新連線時會依正在執行的真實任務恢復模式、花點與種花設定，不再把背景種花錯誤顯示成只有一個點的一般多點巡迴。
- App 在背景執行期間只保留每台裝置最新的座標與種花進度；返回視窗後會直接顯示目前狀態，不會集中補繪過期畫面。
- 畫面更新已與 GPS 定位模擬流程分離；即使桌面或手機遙控畫面進入背景、變慢或中斷，也不會阻塞正在執行的定位任務。
- 花圈與轉場路線只在目前花朵或執行階段改變時更新，減少即時座標及剩餘時間更新造成的地圖負擔。

### 更完整的診斷紀錄與安全恢復

- 保留畫面程序無回應與異常結束的診斷紀錄，方便區分地圖、操作介面與裝置連線問題。
- 改善重新連線後的位置、任務與種花進度同步，降低前端顯示與背景執行狀態不一致的情況。

## What's new

### ArcWayfarer v0.1.15: more reliable iPhone GPS simulation, background operation, and multi-device control

ArcWayfarer v0.1.15 improves iPhone and iPad GPS location simulation on macOS and Windows. Flower mode and route tasks now keep running more reliably when the app is minimized or moved to the background. Restore the window to see the current map, device status, and task progress automatically resynchronized—without restarting the app or rebooting your computer.

### Reliable background operation and smoother map recovery

- Fixed an issue where minimizing ArcWayfarer during Flower mode or another active route could leave the map stalled, blank, or unable to render after restoring the window.
- High Performance map mode now handles WebGL context loss and recovery, then automatically resizes the map, redraws routes, and synchronizes location markers when the window becomes visible again.
- Standard map mode also recalculates its size after window restoration to prevent displaced tiles and controls.
- Fixed the rendering indicator remaining visible after the WebGL context had recovered.
- If High Performance map mode cannot recover, you can reload the map or switch to Standard mode without losing access to the rest of the interface.

### More stable iOS multi-device management

- The three active device slots now retain their assigned devices and prioritize running or paused tasks. A 20-second rescan will no longer move an active Flower device to the waiting list simply because discovery order changed.
- Hidden-device preferences are saved by device identifier and remain in effect when the same device is rediscovered.
- A hide request takes effect for admission immediately, preventing a scan racing location restoration from temporarily reclaiming the device's slot.
- Restoring a hidden device while all slots are occupied places it in the waiting list without replacing a device already in use.
- Background tasks shown in the waiting list can be stopped directly from Device Manager, with the device returned to its real GPS location.
- Restoring the app window now triggers device rediscovery. A device must be absent from two consecutive background scans before it is removed, reducing false disconnections while device services recover.

### Synchronized Flower mode and route progress

- Multi-stop and Flower drafts are saved separately for each device, preserving waypoints and settings through queue changes, panel remounts, and renderer reloads.
- Reconnecting now restores the authoritative running mode, Flower points, and Flower settings instead of showing a background Flower task as a one-point basic multi-stop route.
- While the app is in the background, ArcWayfarer retains only the latest coordinates and Flower progress for each device. Returning to the window shows the current state without replaying stale visual updates.
- UI updates are now isolated from GPS location simulation, so a backgrounded, slow, or disconnected desktop or mobile controller cannot block an active location task.
- Flower rings and transfer paths update only when the active flower or task phase changes, reducing map workload from live coordinates and ETA updates.

### Better diagnostics and safe recovery

- Added diagnostics for an unresponsive or unexpectedly terminated renderer, making map, interface, and device-connection failures easier to distinguish.
- Improved position, task, and Flower progress synchronization after reconnecting to reduce UI/backend state mismatches.
